ПОС - Домашнее задание №2

Логика решения

ПОС - консольное приложение для учёта оценок студентов. В программе можно добавлять студентов и критерии оценивания, менять и удалять их. Для критерия задаются максимальный балл и вес. После этого преподаватель может выставить оценку, исправить её или удалить.

Итоговый балл вычисляется по оценкам и весам критериев и приводится к шкале от 0 до 10. По умолчанию критерии без оценки учитываются как 0 баллов. Также есть расчёт только по критериям, по которым уже поставлены оценки. Данные сохраняются в JSON, а итоговые результаты можно выгрузить в CSV.

Карта DDD

Основные понятия предметной области: студент, критерий, оценка и итоговый балл.

- Student и Criterion - сущности с собственными идентификаторами. Evaluation связывает студента, критерий и оценку.
- Score - объект-значение. Он хранит балл и не допускает отрицательных значений.
- Gradebook - основной агрегат. Через него добавляются и изменяются студенты, критерии и оценки.
- Инварианты: нельзя поставить оценку выше максимума критерия, оценить несуществующего студента или критерий. Для одной пары студент-критерий хранится не больше одной оценки.
- IGradebookRepository - интерфейс для загрузки и сохранения ведомости.
- ScoreCalculator - доменный сервис для расчёта итогового балла.

Архитектура и слои

Используется Ports and Adapters. Проект разделён на четыре части:

- Pos.Domain - модели, правила и расчёт итогов.
- Pos.Application - действия приложения, фасад и интерфейсы для хранения и экспорта.
- Pos.Infrastructure - работа с JSON и CSV.
- Pos.Console - меню и настройка DI-контейнера.

Основные зависимости: Console -> Application -> Domain. Infrastructure зависит от Application и Domain. Домен не обращается к консоли или файлам. Реализации интерфейсов подключаются в Program.cs через DI-контейнер.

Паттерны GoF

- Factory (EvaluationFactory) создаёт оценку и проверяет, не превышает ли балл максимум критерия.
- Facade (PosFacade) собирает основные действия приложения в одном классе, чтобы меню не работало напрямую с ведомостью и хранилищем.
- Strategy (IScoringStrategy) позволяет выбирать расчёт по всем критериям или только по оценённым, не меняя ScoreCalculator.

Роль ИИ

Архитектуру, разбиение на слои и основную логику домена проектировал и писал сам. ИИ использовал как справочник по синтаксису C# (работа с `System.Text.Json`, настройка DI) и для ускорения написания однотипных проверок в юнит-тестах.
